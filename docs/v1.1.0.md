## 完成内容

### 房间与同步

进入加入页面后每秒广播一次查询，房主单播应答，状态变化主动通知浏览端。房间关闭后暂时留在列表中显示“房间已关闭”；异常断线约 4.5 秒超时后也显示关闭，随后清理。只有等待伙伴的兼容房间允许点击；服务器再次验证容量、协议和游戏阶段，处理点击时状态已经变化的情况。

服务端仍是唯一战斗模拟来源。每约 0.1 秒发送压缩状态，数据拆成最多 1,000 字节的分片，全部到齐才应用；过期、不完整和重复快照不会覆盖新状态。装备槽、动作编号、目标、动作进度、玩家生命和技能状态都进入快照。武器攻击、命中和敌人生成不会在客户端独立决定。

### 人物、穿戴、动作与反馈

两位角色共用同一套清晰像素规范，由 image2.5 生成精修母图后整理头部、眼睛、躯干、手臂、脚、手掌与立绘。固定脚底原点进行镜像，避免旧绘制逻辑中反向矩形造成的位置偏移。

穿戴包含头部、身体、背部、主手、副手和饰品；共有 8 件外观装备及 4 类手持武器。外观装备不修改数值，已拥有武器轮流使用，最多两件同时实际握在手中。朝上攻击时手与武器放在身体后方，朝下则在前方。武器柄与手掌使用同一坐标，手臂连接到握持位置。

八类动作通过部件绑定完成：待机呼吸 / 眨眼，移动踏步，近战前摇与挥击，远程瞄准与后坐，受击闪烁 / 轻微摆动，倒地渐变，技能动作，胜利跳跃。一二和布布保留各自微动作。攻击前摇结束时才发生真实判定；投射物从手持武器端点生成，并补充近距离接触检测以避免枪口越过敌人造成漏伤。

保留 UI 风格和结构，加入轻量页面过渡、按钮回弹、房间卡片淡入、生命 / 经验 / 技能 CD 平滑变化、暂停和结算过渡。手机触摸使用原生鼠标模拟驱动 UI，摇杆忽略重复的模拟鼠标事件，避免技能手指释放干扰移动。

## 手动安卓验收建议

1. 两台手机覆盖安装新 APK；分别进入单人，检查摇杆连续转向、移动时同时点技能、暂停与返回。
2. 同一 Wi-Fi 下，一台创建房间，另一台打开房间列表，点击加入；房主开始。第三个浏览端（如电脑）可观察满员 / 已开局状态。
3. 大厅或补给站打开“整理穿戴”，切换帽子、衣服、背部、饰品和手持武器；检查另一端同步显示。
4. 波次结束各自领取成长、购物和准备；打完第六波 Boss；检查双方结算一致。测试倒地靠近救援和情侣技能。
5. 返回菜单关闭房间，确认浏览端状态更新；分别观察单人 / 双人持续战斗时的帧率、温度、音效和震动。

## 当前限制

- 尚未完成两台真实 Android 设备的安装、触摸、多机 Wi-Fi 发现和持续性能验收；以用户手动测试为准。
- 需要同一可互访 IPv4 局域网。访客隔离、VPN 路由或路由器 / 防火墙阻止 UDP 广播时，房间可能不可见；没有手动 IP 兜底入口。
- 1.0.0 未实现发现协议，因此旧房间无法被新版列出；支持发现协议但版本不匹配的房间会显示不兼容。
- 局域网双人不支持中途加入、断线重连或房主迁移；战斗中掉线会结束该局。
- 角色动作是精修像素部件的程序动画，不是每个方向都逐帧手绘的八方向动画。
- 外观部件当前直接可选，无额外解锁系统；武器仍通过原有商店获得和强化。
- 无联网账号、互联网匹配或持久化局外成长。游戏仍是完整六波的一局式玩法。
