# 一二布布 · 大甜莓守护战 v1.3.0

## 本轮修改

- 小波流程为 `X-1 → 补给 → X-2 → 补给 → … → X-6 Boss → 回合结束补给 → (X+1)-1`。普通补给站提供属性成长、武器、装备、饰品、道具、建筑、穿戴与库存调整；双方点击准备后房主才进入下一波。可取消准备。
- 第六波后才出现独立的「核心」页签。九项强化均有专属图标，可使用每人一次免费选择机会，也可用草莓购买。普通小波及首次部署时核心商品在界面和服务端均不可用。
- 弃用旧版帽子、衣服等外观叠层。衣橱改成完整人物外观；对局内外观固定，不增加属性，不提供外观手持物。战斗功能装备和真实武器穿戴照常保留。
- 装备槽、主动道具、建筑库存、分类页签及商店商品卡使用大尺寸图标。空槽有轮廓图标；道具显示 `×1`、快捷编号及冷却；商品展示名称、价格、品质类别和效果；核心强化采用独立图标。
- 保留原有局域网自动发现、房主权威模拟、大甜莓部署与损伤、Boss、建造、救援、双倒地复活和时间停止。

## 新时装与图标

以 `资产/原画/bear_refined.png` 为唯一人物身份参考，通过 `tools/generate_v130.ps1` 调用 image25/image2.5 生成一二、布布各六套：**暖暖日常、花园园丁、森林探险、晚安小熊、春日花语、莓园魔法**。每套均有正面、侧面、背面，合计 12 套、36 张运行时图片。母图在 `资产/原画/v130_*.png`，切片在 `资产/精灵`，预览在 `tests/output/v130_costumes.png`。

新图标共 40 个：六种商品分类、八种空槽、九项核心强化、十一种属性/功能强化、四种旧武器补绘，以及技能/货币等图标。母图为 `v130_icons.png`、`v130_upgrades.png`、`v130_crossbow.png`；切图脚本 `tools/build_v130_assets.py` 依据图像实测边界切割，使用最近邻缩放。图标预览见 `tests/output/v130_icons.png`。生成凭据存于本机 image25 配置，不在项目或 APK 中。

## 验证

| 项目 | 结果 |
| --- | --- |
| 每波补给 | `tests/garden_check.gd` 逐一检查 1-1～1-6 后均进入补给，等待期间不自动推进；两人都准备后才开始下一波 |
| Boss 后核心栏 | 检查普通波次不出现核心库存/不能买、Boss 后九项开放、免费选择和购买；`tests/ui_check.gd` 触屏验证页签翻页 |
| 单人和双人首局 | `tests/simulation_check.gd` 完整模拟一二单人、布布单人及双人六波、Boss、补给、下回合 |
| LAN 补给/准备 | `tools/run_checks.py` 启动真实双进程 ENet，检查自动发现、普通与 Boss 补给、双人准备、装备/时装/核心状态同步、暂停时间、结算 |
| 衣橱和方向 | 触屏衣橱选择；`tests/visual_check.gd` 渲染原版与六套衣服共 42 个角色视角，比较左右转向锚点 |
| APK | Godot 导出后以 `apksigner` 和 `aapt` 检查签名、版本、架构和安装包完整性；安卓安装及双真机联机由玩家手动试玩 |

执行 `python tools/run_checks.py` 复测逻辑、联机和界面。项目直接用 Godot 4.7.2 打开 `project.godot`。Android APK 在 `release/YierBubu-Garden-v1.3.0.apk`。本版 LAN 协议为 4，两台手机需要安装同版 APK。创建房间的手机与加入者需处于可互访的同一 Wi-Fi，UDP 28712/28713 可用。

## 扩展与已知限制

增加角色时在 `scripts/catalog.gd` 增加角色数据，并提供原版及各时装三方向完整贴图；增加武器、敌人、道具和建筑使用 `scripts/catalog.gd` / `scripts/garden_content.gd` 的数据表，再接入 `scripts/simulation.gd` 中实际行为。新增核心成长还需图标并扩展核心升级逻辑。

本机通过 Godot 桌面渲染、模型模拟和双进程联机；尚未在本轮对 Android 真机的触控尺寸、帧率及两台真实手机的 Wi-Fi 连接做实测。现有角色动作用程序动画和方向贴图，尚未为每套时装逐动作绘制独立帧序列。
